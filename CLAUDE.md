## What this is

**Buttress** — a hackathon demo (Qoder × Beta Fund, Agent Factory, Aug 29 2026) pitched as an "agent factory" that runs a **closed, compounding loop** for construction workforce supply: read a firm's project pipeline → forecast which trades fall short → run autonomous recruitment marketing that converts career-switchers into those trades → dispatch them onto the jobs that created the demand.

The full product brief, locked decisions, and the demo script live in `docs/FOUNDRY_HANDOFF.md` ("Foundry" was the old placeholder name; the product is now Buttress). **Read that brief before making product/scope decisions.**

## The one rule that governs the architecture

**The headline number is computed by deterministic plain code, never by the model.** The demo's credibility rests on this. Intake and Forecaster are pure, reproducible functions; the seed data is tuned so the Forecaster derives the hero gap ("**12 electricians short in Phoenix, needed by week 6 / 2026-10-26**") with no randomness. `agents/forecaster.test.ts` locks that number and its determinism — keep those tests green.

A load-bearing modeling choice: `agents/intake.ts` takes `Math.max` (not sum) across overlapping same-trade phases — "peak concurrent crew." Changing it to a sum changes the headline gap from 12. Don't touch it without re-tuning the seed and tests, and keep the assumption surfaced in the UI.

## The agent fleet (the loop)

Every node is an `Agent<Input, Output>` (`agents/types.ts`) — a named, single-purpose function with a typed contract, so the factory can wire them mechanically and each is testable alone. Depth is deliberate, per node:

| Node | File | Kind |
|---|---|---|
| Intake (demand engine) | `agents/intake.ts` | **Deterministic** — schedule → labor-demand curve |
| Labor Gap Forecaster | `agents/forecaster.ts` | **Deterministic** — demand vs. roster → the gap signal |
| Campaign (the wedge) | *(planned)* | **Live Groq** — the hero on-screen generation |
| Nurture | *(planned)* | Light Groq for one message; candidate inflow is **simulated + labeled** |
| Screening | *(planned)* | **Deterministic** — candidate → cert/apprenticeship path |
| Dispatch | *(planned)* | **Deterministic** — assign credentialed workers → the job |

Rule of thumb: **only Campaign does live AI on stage** (speed + wow, worth the risk). Everything the headline number depends on stays deterministic. Candidate inflow is always simulated and must be labeled "simulated" on screen (`Candidate.simulated` is always `true`).

## State & runtime model

- **No database.** State is client-orchestrated from a static TS seed (`data/seed.ts`). Vercel serverless is stateless, so in-memory persistence across requests is intentionally avoided.
- **API routes are stateless** — used only for Groq LLM calls (server-side, key hidden).
- `AgentContext.demoMode` (`agents/types.ts`): when true, generative agents return **pre-baked output** instead of calling the model — the offline-safe path for a live stage demo. Build every generative agent with this fallback.
- LLM = **Groq** (`groq-sdk`, OpenAI-protocol) for the live generation.

## Layout

- `lib/domain.ts` — shared entity types (the vocabulary every agent speaks).
- `data/seed.ts` — the one demo firm, project, and simulated candidate pool.
- `agents/` — one file per agent + the `Agent<I,O>` contract in `types.ts`; tests colocated (`*.test.ts`).
- `app/` — Next.js App Router; the landing page and the single-screen demo run.
- `design/` — reference-only design mockups; `design/reference/` holds the v0 "Sprint" (Linear-clone) template screenshots the landing + demo pages are built to match (dark, isometric, animated closed loop).
- Planned: `lib/metrics.ts` (deterministic baseline-vs-measured efficiency multiple, unit-tested) and `factory/` (emits the fleet as owned `.ts` code — the Qoder "we hand you a codebase, not a flowchart" differentiator).

## Commands

```bash
npm run dev            # Next.js dev server
npm run build          # production build
npm run lint           # eslint
npm run test           # vitest run (all tests, once)
npm run test:watch     # vitest watch mode
npx vitest run agents/forecaster.test.ts   # a single test file
npx vitest run -t "deterministic"          # tests matching a name
```
